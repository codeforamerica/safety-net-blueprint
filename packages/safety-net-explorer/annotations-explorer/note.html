inputs medicaidWorkRequirements.determination.date
The draft asked for the year of the decision, as an integer. The ruleset asks for the day it's decided, as a date, so a start partway through a year, like Iowa's December 1, 2026, can be expressed. A renewal is never asked this to decide whether the requirement applies; it's still asked for the proof rules (beforeDocumentationRequired).
inputs medicaidWorkRequirements.determination.exemptAtLastDetermination
Same question, with "exempt" for the draft's "excluded".
inputs medicaidWorkRequirements.determination.renewalStartedOn
The draft asked yes or no: was the application submitted, or the renewal started, before the requirement took effect? The ruleset asks for the day a renewal started, as a date, and only renewals read it, because 42 CFR 435.559(c) excuses only a renewal started before the start. The draft also excused an application submitted before, which 435.559 doesn't say.

facts medicaidWorkRequirements.requirementInEffect
Follows 42 CFR 435.559. A renewal is checked if it started on or after effectiveDate (435.559(c)); anything else, if it's decided on or after it, since coverage from then on is subject (435.559(a)). The draft compared the decision year and excused anything started before, applications included. Written as a conditional so a renewal is never asked its decision date here, nor an application its start.

facts snapWorkRequirements.exemptions
Leaves out the age codes the tool puts first. Read as a set; the tool keeps an order for its exemptions_found record. The ruleset declares no item list or uniqueness, where co-snap declared both. It also waits on every exemption question. So for someone exempt by, say, pregnancy, it waits on isWorking, a question the tool skips once has_exemption? is true.
facts snapWorkRequirements.hasExemption
The tool checks non_earnings_exemption_reasons.any?. Like the tool, it counts age, so it is true for a 70-year-old whose isExempt is false. The tool uses it to skip the work, volunteering and training questions.
facts snapWorkRequirements.hasOtherExemption
The yes answers in Screener::OTHER_EXEMPTION_ATTRIBUTES, gathered so hasExemption can read one fact.
facts snapWorkRequirements.hasStateExemption
Whether the state adds an exemption, as a yes or no the state's overlay replaces. The tool gets the same answer by checking whether non_earnings_exemption_reasons, which includes state_exemption_reasons, has anything in it.
facts snapWorkRequirements.isAgeExempt
The tool checks for the under_18 or 65_or_older range. The ruleset compares the age with two constants, through the two age facts.
facts snapWorkRequirements.isExempt
requirementApplies and isExemptFromWorkRules. False for someone age-exempt, where the tool's exempt_from_work_rules? is true. It matches the tool's exempt outcome, which only people past the age check reach. An earnings exemption counts, as in the tool.
facts snapWorkRequirements.isExemptFromWorkRules
The tool checks exemption_reasons.any?; the ruleset joins hasExemption and hasEarningsExemption with or. It still counts age, as the tool does. co-snap made it an output; the ruleset keeps it as a fact only, and isExempt is the output.
facts snapWorkRequirements.meetsRequirement
co-snap's compliesWithWorkRules, renamed to Medicaid's word.
facts snapWorkRequirements.notApplicableReason
Which age cutoff the person is past: under_minimum_age or over_maximum_age, else applies. The tool's codes were age_under_18 and age_65_or_older; co-snap's were age_under_minimum and age_over_maximum. The applies value has no counterpart.
inputs snapWorkRequirements.person.age
The tool asks for one of five ranges; the ruleset takes an age in whole years, at least 0, with no upper limit. The tool also asks for a birth date later on (screeners.birth_date), but no rule reads it.
inputs snapWorkRequirements.person.isInWorkTraining
No rule in the tool reads is_in_work_training; it only clears the training hours on save when the answer is no. co-snap kept it as an input nothing read. The ruleset reads it to decide whether training hours count.
inputs snapWorkRequirements.person.isVolunteer
The tool's rules read is_volunteer only in volunteering?, for proof. The ruleset also reads it to decide whether volunteering hours count toward the 20.
inputs snapWorkRequirements.person.isWorking
The tool's rules read is_working only for the earnings exemption. The ruleset also reads it to decide whether working hours count toward the 20.
inputs snapWorkRequirements.person.workingWeeklyEarnings
A decimal column in the tool, cleared when is_working is no. The ruleset reads it even for someone who doesn't work (see earningsAboveMinimum), so it can be asked of a person the tool would never ask.
inputs snapWorkRequirements.person.workTrainingHours
The tool stores this as a string column, validates it as a whole number, and reads it with to_i. The ruleset takes an integer.
facts snapWorkRequirements.receivingDisabilityBenefits
The tool loops over DISABILITY_BENEFIT_ATTRIBUTES. The ruleset joins the eight exemption facts with or. co-snap called this same; the answer is the same, but the shape is that of hasExemption, which co-snap called changed.
facts snapWorkRequirements.requirementApplies
Not age-exempt. Careful with the words: in the tool, the "work rules apply" pages (WorkRulesApplyMetController, WorkRulesApplyUnmetController) mean the person isn't exempt at all. Here requirementApplies is only about age, and stays true for someone exempt.
facts snapWorkRequirements.requiresProof
The same expression as the tool's. Two things differ. Through earningsAboveMinimum, it waits on earnings from someone who doesn't work, where the tool reads 0. And the ruleset answers it for everyone, so a 70-year-old student gets true; the tool shows it only on the proof page, which only people exempt for a reason other than age reach.

facts snapWorkRequirements.satisfiesRequirement
True when the requirement doesn't apply, the person is exempt, or the hours are met; false only for the tool's not_exempt_work_rules_not_met. The four-way outcome is gone; it can be rebuilt from requirementApplies, isExempt and meetsRequirement.
facts snapWorkRequirements.totalWorkVolunteerAndTrainingHours
The tool adds working_hours, volunteering_hours and work_training_hours whatever the yes-or-no answers say, reading blanks as 0. Through the tool's screens the total is the same, because a no clears the hours on save. Called directly, it differs: the tool's own spec adds 5, 7 and 9 hours with no yes-or-no answers and gets 21; the ruleset waits on isWorking, isVolunteer and isInWorkTraining.
