/events
GET POST GET /stream GET /{eventId}

The centralized log of domain events across every domain, as CloudEvents 1.0 envelopes. Supports REST polling and a live stream, and keeps a permanent audit history whether or not a message broker is in use.

Publishing records an event a domain producer emits. It is for systems recording what happened, not for requests made on a person's behalf.

Events

Centralized event log across all domains.

▶ GET /events List events listEvents #

Queryable log of all domain events across the blueprint. Supports REST polling as an integration pattern and provides permanent audit history regardless of whether a message broker is in use.

Events are returned in ascending time order (oldest first) to support cursor-based polling.

Returns EventList

Query parameters

q string

Search query using field:value syntax. Multiple conditions separated by spaces are ANDed together.

More

Examples

  • john — exact match for "john" in searchable fields
  • *john* — contains "john" in searchable fields
  • name:*smith* — name contains "smith" (case-insensitive)
  • email:*@example.com — email ends with "@example.com"
  • status:approved — exact match on status field
  • status:approved,pending — status is "approved" OR "pending"
  • income:>=1000 — income greater than or equal to 1000
  • created:>2024-01-01 — created after January 1, 2024
  • status:approved income:>=1000 — approved AND income >= 1000 (multiple conditions)
  • -status:denied — exclude records with status "denied"
  • -deletedAt:* — only records where deletedAt does not exist

Lists

A condition on a list matches when any item matches. That holds for a list of values (programs:snap) and for a list of objects anywhere along a dotted path (members.firstName:Jo, any member named Jo).

Each condition is checked on its own. members.firstName:Jo members.age:>60 matches when some member is named Jo and some member, not necessarily the same one, is over 60. There is no way to require the same item.

sort string

Comma-separated list of fields to sort the response by. Prefix a field with - for descending order. The first field is the primary sort; subsequent fields are tie-breakers in declaration order.

More

Examples

  • sort=createdAt — oldest first
  • sort=-createdAt — newest first
  • sort=-priority,dueDate — highest priority first, then oldest due date
  • sort=name.lastName,name.firstName — alphabetical by surname, then given name

Allowed fields

Which fields a given list endpoint allows is declared in the operation's x-sortable.fields extension. Sending a field name not present in that list returns 400 FIELD_NOT_SORTABLE. Sending a field name that doesn't exist on the resource schema returns 400 INVALID_SORT_FIELD. When this parameter is omitted, the operation's x-sortable.default (if declared) is applied; otherwise no client-driven sort is applied. A configured tie-breaker (default id) is always appended for stable pagination.

See api-patterns.yaml#sorting for the full convention and docs/architecture/x-extensions.md for the extension shape.

type string

Filter by CloudEvents type. Supports prefix matching with a trailing wildcard (e.g., intake.*). When states apply an x-event-type-prefix overlay, the resolved prefix is prepended to all event types (e.g., org.example.intake.*).

source string

Filter by CloudEvents source (the domain that produced the event, e.g., /intake, /workflow).

subject string · uuid

Filter by CloudEvents subject — the entity ID the event pertains to. Because every domain uses the same subject for the same entity, this returns a complete cross-domain timeline for that entity.

traceid string

Filter by W3C Trace Context trace ID extracted from the traceparent attribute. All events sharing a trace ID were causally triggered by the same root action.

causationid string · uuid

Filter by the causationid extension — the ID of the event that directly caused this one. Use it to find the response event(s) produced by a specific trigger (e.g., the call.completed fired for one service_call.created when several were emitted for the same subject).

start string · date-time

Return only events at or after this timestamp (ISO 8601).

end string · date-time

Return only events before or at this timestamp (ISO 8601).

limit integer

Maximum number of items to return (1-100).

offset integer

Number of items to skip before collecting results.

▶ GET /events/stream Stream domain events (SSE) streamEvents #

Real-time stream of domain events delivered as Server-Sent Events (SSE).

Connect with Accept: text/event-stream. Each event is one SSE message: an id: line with the event's id, and a data: line with the JSON-encoded Event.

To pick up after a dropped connection, reconnect with the last id received in Last-Event-ID, as a browser's EventSource does on its own: the stream first sends every matching event after that one, in the order they happened, then carries on live. An id the log no longer has is answered 410 Gone, so a reader never quietly misses events; it reads what it needs afresh and connects again without one.

The filters are the ones listing events takes.

A server that can't hold a connection open — behind an API gateway that ends requests early, say — may leave the stream out and answer 501. Readers then poll listing events, with the same filters and start, which every server serves.

The stream stays open until the client disconnects. A : heartbeat comment is sent every 30 seconds to prevent proxy timeouts.
