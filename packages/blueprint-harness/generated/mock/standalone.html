Not your average mock server

Returning canned JSON is a solved problem. This does something else: it is generated from contracts, so it knows your application is in the wrong state to be closed, that a 72-hour deadline just elapsed, and which regulation a timestamp exists to satisfy.

Nothing below was configured or hand-written. Every route, rule, state transition and response shape was derived from the same contract documents an implementation would be built against — which is the point: if the mock works, the contracts are executable, not just documentation. Each step shows the contract first, then runs it.

And it is all running in this tab. No server, no network, no install.

There is no server, so there is nothing shared. Everything above runs in this tab against its own in-memory store — another person opening this page cannot affect your run, and you cannot affect theirs. Two tabs are two independent systems. That is worth noting because it is the usual failure of a hosted mock: one person resetting the data or registering a stub disrupts everyone else using it.

Refreshing starts over from the contracts. Nothing persists, nothing is uploaded, and no request leaves the page — including the document in the upload step, whose bytes are measured and discarded.
