The written record of a conversation. Starting a transcript opens it for recording; pausing takes the conversation off the record; closing ends it. A transcript refers to what it records — an interview, a call — and names the profile it was started under, which says the transcription service, and the client and model that produced its lines. Updating corrects what it records; deleting removes it, and the event left behind says which one and by whom.

A profile is a state's choice of transcription service and languages for a kind of conversation. The deployment's config seeds them; they can be added and changed here, never deleted, so every transcript's profile still exists.

Its entries are its timeline, in the order things happened: lines, gaps where nothing was captured, and pauses. Every time on a transcript and its entries is the client's — when it started, paused, resumed and closed, and when each line was said — so they are compared on one clock.

▶ GET /transcripts List transcripts listTranscripts #

Retrieve a paginated list of transcripts. Filter by subjectId to find the transcripts of one interview or call.

Returns TranscriptList

Query parameters

q string

Search query using field:value syntax. Multiple conditions separated by spaces are ANDed together.

More

Examples

  • john — exact match for "john" in searchable fields
  • *john* — contains "john" in searchable fields
  • name:*smith* — name contains "smith" (case-insensitive)
  • email:*@example.com — email ends with "@example.com"
  • status:approved — exact match on status field
  • status:approved,pending — status is "approved" OR "pending"
  • income:>=1000 — income greater than or equal to 1000
  • created:>2024-01-01 — created after January 1, 2024
  • status:approved income:>=1000 — approved AND income >= 1000 (multiple conditions)
  • -status:denied — exclude records with status "denied"
  • -deletedAt:* — only records where deletedAt does not exist

Lists

A condition on a list matches when any item matches. That holds for a list of values (programs:snap) and for a list of objects anywhere along a dotted path (members.firstName:Jo, any member named Jo).

Each condition is checked on its own. members.firstName:Jo members.age:>60 matches when some member is named Jo and some member, not necessarily the same one, is over 60. There is no way to require the same item.

URL encoding

This parameter must be URL-encoded when sent over HTTP. Most HTTP clients handle this automatically. Examples in this documentation show human-readable syntax for clarity. - applicant.state:CA — nested field filter

limit integer

Maximum number of items to return (1-100).

offset integer

Number of items to skip before collecting results.

sort string

Comma-separated list of fields to sort the response by. Prefix a field with - for descending order. The first field is the primary sort; subsequent fields are tie-breakers in declaration order.

More

Examples

  • sort=createdAt — oldest first
  • sort=-createdAt — newest first
  • sort=-priority,dueDate — highest priority first, then oldest due date
  • sort=name.lastName,name.firstName — alphabetical by surname, then given name

Allowed fields

Which fields a given list endpoint allows is declared in the operation's x-sortable.fields extension. Sending a field name not present in that list returns 400 FIELD_NOT_SORTABLE. Sending a field name that doesn't exist on the resource schema returns 400 INVALID_SORT_FIELD. When this parameter is omitted, the operation's x-sortable.default (if declared) is applied; otherwise no client-driven sort is applied. A configured tie-breaker (default id) is always appended for stable pagination.

See api-patterns.yaml#sorting for the full convention and docs/architecture/x-extensions.md for the extension shape.

▶ GET /transcripts/{transcriptId}/entries List a transcript's entries listTranscriptEntries #

A transcript's timeline, in the order things happened — by startedAt. Filter by kind for only its lines, gaps or pauses.

To fetch only entries added since the last read, search on createdAt, which the server sets when it stores an entry: q=createdAt:>=<the newest createdAt already read>, skipping ids already read. startedAt is the client's clock, so a line can arrive after one that started later than it; createdAt still puts it after the last read.

A condition on a list matches when any item matches. That holds for a list of values (programs:snap) and for a list of objects anywhere along a dotted path (members.firstName:Jo, any member named Jo).

▶ POST /transcripts/{transcriptId}/entries Add an entry to a transcript addTranscriptEntry #

Add a finished line, or a gap where nothing was captured. Pauses are not added here: pausing the transcript adds one.

Send an Idempotency-Key with every add, and the same key when retrying one, so a retry is not a second line. The transcript refuses an entry that started while it was paused or after it closed, an entry that ends before it starts, and a gap that overlaps a pause.

Path parameters

transcriptId string · uuid required

Unique identifier of the transcript.

Headers

Idempotency-Key string required

A key the client makes for one request that creates or changes records, so a retry doesn't make them twice. Send the same key with every retry of the same request: the first is carried out, and a repeat gets the same response back. The same key with a different request is refused with 422. Keys are scoped to the caller.

More

Any value unique to the operation works; a UUID is recommended. An operation that lists this parameter requires it. Follows the IETF HTTP API working group's Idempotency-Key header draft, and the convention Stripe and others use.

Lists

A condition on a list matches when any item matches. That holds for a list of values (programs:snap) and for a list of objects anywhere along a dotted path (members.firstName:Jo, any member named Jo).

Each condition is checked on its own. members.firstName:Jo members.age:>60 matches when some member is named Jo and some member, not necessarily the same one, is over 60. There is no way to require the same item.

Comma-separated list of fields to sort the response by. Prefix a field with - for descending order. The first field is the primary sort; subsequent fields are tie-breakers in declaration order.

More

Examples

  • sort=createdAt — oldest first
  • sort=-createdAt — newest first
  • sort=-priority,dueDate — highest priority first, then oldest due date
  • sort=name.lastName,name.firstName — alphabetical by surname, then given name

Allowed fields

Which fields a given list endpoint allows is declared in the operation's x-sortable.fields extension. Sending a field name not present in that list returns 400 FIELD_NOT_SORTABLE. Sending a field name that doesn't exist on the resource schema returns 400 INVALID_SORT_FIELD. When this parameter is omitted, the operation's x-sortable.default (if declared) is applied; otherwise no client-driven sort is applied. A configured tie-breaker (default id) is always appended for stable pagination.

See api-patterns.yaml#sorting for the full convention and docs/architecture/x-extensions.md for the extension shape.
