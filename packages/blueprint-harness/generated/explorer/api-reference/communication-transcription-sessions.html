Transcription sessions 2Transcription Sessions 11

The transcription software's connection to its transcription service, for one browser tab. Designed to run in the page, beside the software, while the transcript it writes to lives on the server.

Creating a session says which transcript it writes to: an existing one, to carry on after a session failed, or what to start a new one with. A new transcript is started the first time the software asks how to stream. The session's actions are what the page and the client adapter tell it — how do I stream, the connection is open or dropped, a line in progress or finished, pause, resume, stop, close, give up — and each sends an event, which is how the page and the client adapter follow it.

Base URL: https://api.example.com/communication

▶ POST /transcription-sessions Start a transcription session #

Start keeping track of the software's connection, for a transcript. Name an existing transcript with transcriptId to carry on after a session failed; otherwise give what a new transcript is started with — profileId, client and startedAt, and model unless the profile's service is none — and it's started the first time the software asks how to stream. The session begins in created.
