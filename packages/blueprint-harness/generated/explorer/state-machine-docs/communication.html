Communication State Machine

Domain: communication · API: communication-transcription-sessions-openapi.yaml, communication-transcripts-openapi.yaml

TranscriptionSession

States

StateDescriptionSLA clock
created Started, not yet connecting. stopped
connecting The software has, or is getting, where to connect and a credential, and is opening the connection. stopped
connected Audio is going to the service and text is coming back. stopped
disconnected The connection dropped, and the software is trying again. stopped
paused Off the record. The connection is closed, so no audio leaves the page. stopped
stopping Stop was asked for; the last audio is sent and the last text is still coming. stopped
closed Done, and the transcript is closed. Terminal. stopped
failed The software gave up connecting or reconnecting. The transcript stays open; a new session can carry on under it. Terminal. stopped

Actions

ActionActorsTransitionSteps
get-connection API →
Get where to connect and a short-lived credential, starting the transcript the first time.		 createdordisconnectedorconnecting→connecting
  • If !has(object.transcriptId):
    • Call POST /communication/transcripts with profileId, model, client, startedAt, subjectType, subjectId
    • sets transcriptId
  • Call POST /communication/transcripts/{transcriptId}/get-connection with audio, protocols
  • Emit communication.transcription_session.connecting
renew-connection API →
Get a fresh credential while connected, with no change to the session.		 no state change
  • Call POST /communication/transcripts/{transcriptId}/get-connection with audio, protocols
connect API →
The connection to the service is open. A stretch with nothing captured, after a reconnect or before carrying on a transcript, is recorded as a gap.		 connecting→connected
  • If has(request.gap):
    • Call POST /communication/transcripts/{transcriptId}/entries with kind, startedAt, endedAt, cause
  • Emit communication.transcription_session.connected
disconnect API →
The connection to the service dropped; the software will try again.		 connected→disconnected
  • Emit communication.transcription_session.disconnected
update-line API →
A line in progress, to show. Nothing is kept; it's tied to its finished line by its key.		 no state change
  • Emit communication.transcription_session.line_updated
add-line API →
A finished line, added to the transcript with its key, so a retry adds it once. Allowed while paused, for the last text before the pause; the transcript keeps it if it started before.		 no state change
  • Call POST /communication/transcripts/{transcriptId}/entries with kind, startedAt, endedAt, text, speaker, speakerLabel, confidence, language
  • Emit communication.transcription_session.line_added
pause API →
Take the conversation off the record. The transcript keeps the pause; the software closes the connection.		 connected→paused
  • Call POST /communication/transcripts/{transcriptId}/pause with at
  • Emit communication.transcription_session.paused
resume API →
Put the conversation back on the record. The software then asks how to stream again. From created, a new session carries on a paused transcript.		 createdorpaused→connecting
  • Call POST /communication/transcripts/{transcriptId}/resume with at
  • Emit communication.transcription_session.connecting
stop API →
Finish. The software sends the end of the audio and waits for the last text, or closes at once when no connection is open.		 connectedorpausedordisconnected→stopping
  • Emit communication.transcription_session.stopping
close API →
The last text is in and the connection is closed; the transcript closes.		 stopping→closed
  • Call POST /communication/transcripts/{transcriptId}/close with at
  • Emit communication.transcription_session.closed
fail API →
The software gave up connecting or reconnecting. The transcript stays open.		 connectingordisconnected→failed
  • Emit communication.transcription_session.failed

Transcript

States

StateDescriptionSLA clock
recording The conversation is on the record; lines are accepted. stopped
paused The conversation is off the record — an applicant asked, say. Nothing said now is stored. stopped
closed The transcript has ended. Terminal. stopped

Actions

ActionActorsTransitionSteps
pause API →
Take the conversation off the record, at the time the client says.		 recording→paused
  • Call POST /communication/transcripts/{transcriptId}/entries with kind, startedAt, endedAt
  • Emit communication.transcript.paused
resume API →
Put the conversation back on the record, at the time the client says. Already recording, nothing changes.		 pausedorrecording→recording
  • If openPause is not null:
    • Call PATCH /communication/transcripts/{transcriptId}/entries/{entryId} with endedAt
    • Ask the scheduler for an idle check after the profile's idleTimeout, if it sets one.
    • Emit communication.transcript.resumed
get-connection API →
Get what the software needs to stream the conversation's audio to its transcription service — where to connect, and a short-lived credential.		 no state change
  • Call POST /issue-connection with provider, model, languages, audio, protocols, metadata
close API →
End the transcript, at the time the client says. A pause still open ends then too.		 recordingorpaused→closed
  • sets closedAt
  • If openPause is not null:
    • Call PATCH /communication/transcripts/{transcriptId}/entries/{entryId} with endedAt
  • Cancel the idle check of a transcript that was closed. One that already fired is closing it, and the cancel does nothing.
  • Emit communication.transcript.closed
